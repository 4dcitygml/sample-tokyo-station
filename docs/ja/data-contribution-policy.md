# データ貢献ポリシー（属性・幾何・テクスチャ・写真の取り扱い）

status: v2（v1「写真提供ポリシー」を全データ貢献に拡張）

本リポジトリの**データファイル（データディレクトリ配下の CityGML・テクスチャ画像）への
貢献**の権利の取り扱いを定めます。データを変更する PR を提出した時点で、提出者は本ポリシーに
同意したものとします（各ツールは PR 本文にその旨を記録します）。

English (canonical): [docs/data-contribution-policy.md](../data-contribution-policy.md)

## 1. データへの貢献はすべて CC0 1.0

- 提出者は、データへの貢献（属性値・幾何の修正、テクスチャ、写真）を、**それに権利が
  発生する限りにおいて [CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/deed.ja)**
  （パブリックドメイン提供）として提供します。
- 属性値（階数・用途コード・浸水深など）や幾何（座標）の修正は**事実・データ**であり、
  通常はそもそも著作物性がありません。本条は「万一権利が発生していても CC0」という
  安全側の宣言です（構造化データを CC0 とする Wikidata と同じ方式）。
- 写真は独立性の高い著作物のため、法域によっては放棄・譲渡できない**著作者人格権を
  行使しないこと**（日本法など）にも同意します（テクスチャ化の過程で切り抜き・台形補正・
  合成・再圧縮などの改変を受けます）。
- **コード・ドキュメントへの貢献は本ポリシーの対象外**です。従来どおり GitHub 利用規約
  （D.6 inbound=outbound）によりリポジトリのライセンス（Apache-2.0）に従います。
- リポジトリ全体としてのデータ配布は、原典のライセンスに従います（リポジトリ README と
  `4dcitygml.json` を参照。例: PLATEAU 由来データは CC BY 4.0）。CC0 素材の統合は
  これと矛盾しません。

## 2. 写真を提出する場合の追加条件

1. **自分で撮影した写真**であること（他者の撮影物・Web上の画像・SNS からの転載は不可）。
2. **公道など適法な場所から撮影**したものであること。
3. **肖像権・個人情報への配慮**: 次が判読できる写真は、避けるか、その部分をマスク・
   ぼかししてから提出してください。
   - 人の顔・容姿（通行人・住人）
   - 車のナンバープレート
   - 表札・室内・洗濯物などの生活情報
4. **第三者の著作物の写り込み**: 各法域の著作権法は通常、建築物の外観の写真利用と、
   看板・ポスター・ディスプレイ等の**付随的な**写り込みを許容しています（日本では
   著作権法46条・30条の2）。それらが写真の主要な部分を占める場合は避けてください。

テクスチャエディタは PR 作成時にこれらへの同意チェックを求めます（写真は実体のある
著作物のため明示同意）。属性エディタは同意チェックなしで PR 本文への記録のみです —
**摩擦は権利リスクに比例させる**という設計です。

## 3. 貢献の記録と顕彰（著作権とは独立）

- 貢献は git の履歴に永続的に記録されます（コミットの author・`Building:` trailer）。
  `git log --grep "Building: <id>"` や author 集計で「誰がどの建物に貢献したか」を
  追跡できます。
- この記録に基づく貢献の可視化・表彰（コントリビュータ一覧・感謝状等）は、
  著作権の帰属とは独立した運用として行うことがあります。

## 4. 削除の申し出

- 肖像権・プライバシー等の問題が事後に判明した画像は、Issue でお知らせください。
  現行データからは速やかに削除します。
- git の性質上、**過去の履歴には削除後もデータが残ります**。人格権・プライバシーに関わる
  重大な場合は、履歴からの除去（history rewrite）を含めて管理者が対応を検討します。

## 付録: 検討の記録

本ポリシー制定時の検討過程の要約です（経緯の透明性のため残す）。

**比較した方式**:

| 方式 | 例 | 評価 |
|---|---|---|
| プラットフォーム許諾型（著作権は投稿者に残し、運営に広範な許諾） | Google マップのクチコミ | 単一運営者の表示利用には適するが、オープンデータの再配布には帰属管理が残る |
| 集合帰属型（投稿規約で財団へ許諾、「© contributors」の集合表記） | OpenStreetMap | 実績は堅い。ただし規約文書と運用の重さがある |
| **CC0型（事実データはパブリックドメイン提供）** | **Wikidata** | **採用**。後段の利用者（自治体・研究者・企業）が写真・画像ごとの帰属管理なしで利用できる |

**決め手**:

1. **帰属スタッキングの回避** — 写真ごとに CC BY を採ると、テクスチャ1枚ごとの帰属を
   NOTICE で永久管理することになり、原典由来テクスチャと混在するフォルダで破綻しやすい。
2. **著作者人格権** — 法域によっては放棄・譲渡できない（日本: 著作権法59条）ため、CC0 に
   加えて不行使への同意を明示（テクスチャ化は改変を伴うため同一性保持権への手当てが必須）。
3. **属性・幾何への拡張（v2）** — 事実データには著作物性がなく宣言は実質空振りだが、
   コストゼロで曖昧さが消えるため安全側に倒した。ただし「全ての PR」ではなく
   **データ貢献に限定**（コードまで CC0 にすると Apache-2.0 体系と不整合になる）。
4. **摩擦設計** — 明示同意（チェックボックス）は実体のある著作物（写真）だけに課し、
   著作物性のない属性編集には PR 本文への自動記載のみとする。
5. **貢献の顕彰は著作権と独立** — git 履歴（author・`Building:` trailer）が貢献台帳を
   兼ねるため、CC0 でも「誰の貢献か」は永続的に追跡できる。
