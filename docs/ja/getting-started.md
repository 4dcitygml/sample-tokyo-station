# はじめかた: クローンから最初の変更提案まで

この案内は、練習の流れを最初から最後まで通して説明します。リポジトリを自分の PC に
取得し、共有編集ツールを起動し、GitHub アカウントとつなぎ、最初の変更提案
（Pull Request）を送るところまでです。初回は 15 分ほどかかります。都市データを直接
書き換える操作はありません。すべての編集は提案になり、自動検査を通ったうえで自治体の最終承認者が承認します。

その後: 自動検査は数分以内に実行されて報告を投稿し、自治体の最終承認者が承認します。誰かが変更を依頼した場合をのぞき、あなたは何もする必要がありません。提案が守るべき規則は [PR 運用手順](pr-operations.md)
と [出典記録の規則](provenance-rules.md) を参照してください。
投稿できる内容は [データ投稿ポリシー](data-contribution-policy.md) をご覧ください。

## 1. クイックスタート: ワンコマンド

Git も GitHub アカウントも、都市データのコピーも要りません。足りないものはツールが
案内します。ここが全体のインストール手順です。すべてのコンピュータで同じで、古くなりません。

- **macOS**: *ターミナル*を開きます（Spotlight → 「ターミナル」）。このリポジトリの
  README（「はじめかた」の項）から次の行をコピーし、Enter キーを押します。

  ```
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/4dcitygml/tools/install-v1/install/citygml.sh)" -- 4dcitygml/sample-tokyo-station
  ```
  macOS がコマンドラインツールのインストールを勧めたら、受け入れて、もう一度実行します。ターミナルが書類フォルダへアクセスしてよいか聞かれたら、許可します。

- **Windows**: *PowerShell* を開きます（スタート → 「PowerShell」）。README の行をコピーし、
  Enter キーを押します。Git と Python はダウンロード物に入っています。それ以外は何も
  インストールされません。

起きることの順番:

1. コマンドは `4dcitygml/tools` の最新リリースを取得し、GitHub が公開している SHA-256
   ダイジェストに対して検証します。ダイジェストが一致しなければ、何もインストールされず、
   コマンドは止まります。
2. ツールは `~/Documents/citygml-tools/citygml-hub/<version>/` に配置され、
   ランチャースクリプトのコピーは `~/Documents/citygml-tools/` に残ります。
3. hub がブラウザで開き、この都市に接続済みの状態になります。作業中はターミナルの窓を
   開いたままにしてください。閉じるとツールが止まります。
4. 次の設定の後、hub はこの都市の **デスクトップ・アイコン** を作成することを提案します。
   そこからは、このアイコンでツールを開きます。コマンドラインは初回か別のコンピュータの
   ときだけです。

このリポジトリはデータ、文書、設定だけを持ちます。コンピュータで実行するプログラムはすべて
`4dcitygml/tools` リリースから来ます — すべての都市で同じです。

## 2. 用意するもの

- macOS 12 以降、または Windows 10 以降。
- macOS のみ: Apple のコマンドラインツール（`git` と `python3`）。初回の実行でインストール
  を勧めるダイアログが出たら受け入れます。Windows は何も要りません: Git と Python はダウンロード物に同梱されています。
- ディスク空き容量 約 400 MB（ツールと都市データのコピー）。
- GitHub アカウントは、次の「つなぐ」の段階で作成できます（無料。メールアドレスとパスワード）。

## 3. Git や GitHub を使い慣れている方へ: このガイドの末尾をご覧ください

ワンコマンド起動は、開発者を含むすべての人にとって最短の入り口です。Git と GitHub を
直接使いたい方、自分のツールを作りたい方は、ここを読んだあとに
[発展: Git・GitHub・自作ツール](#発展-gitgithub自作ツール) をご覧ください。提案が満たすべき
規則はどの経路でも同じです。

## 4. hub の初期設定（3 ステップ）

自分用の作業コピーができるまで、hub は 3 ステップの設定画面を表示します。

1. **つなぐ**: 画面には、許可する内容が書かれています。`public_repo` 権限で、
   ツールはあなたの代わりに公開リポジトリのコピーを作成し、Pull Request を開くことが
   できるようになります。「番号をコピーして GitHub を開く」をクリックし、開いた
   GitHub のページに番号を貼り付けて、確認します。サインインだけでは公開の痕跡は残りません。
   許可はあなた自身の GitHub 設定にだけ記録され、いつでも取り消せます。
2. **コピーを作る**: hub がこのリポジトリをあなたのアカウントに fork します。この時点から、
   コピーは GitHub の fork と同じく、あなたの名前で公開されます。
3. **取り込む**: hub がコピーを `~/Documents/CityGML Data/` に clone します（同名フォルダが
   あれば番号付きのフォルダになります）。大きな都市では数分かかります。

3 つ目が終わったら「はじめる」をクリックします。失敗した場合はボタンが再試行に変わります。
多くはネットワークの一時的な切断が原因です。

## 5. hub の画面

設定後、hub にはツールと自分の提案が並びます。

- **属性エディタ**: 地図から建物の属性を見て編集し、提案を送る。
- **テクスチャエディタ**: 外壁テクスチャの差し替え・追加（都市がテクスチャを持つ場合のみ）。
- **自分の投稿**: 送った提案（と issue）、自動検査の結果・レビュー状況。

各ツールは新しいタブで、それぞれのローカルポートで開きます。作業コピーの場所も hub に表示されます。

## 6. 最初の変更提案

属性エディタで:

1. 地図のメッシュ枠をクリックすると、そのメッシュの建物の足元が表示されます。
2. 建物をクリックすると、3D プレビューと属性カードが開きます。
3. 値をクリックして編集します。変更した値は黄色で示されます。
4. 値を確定すると同じ行に出典欄が開きます。確認した資料を選んでください。出典のない
   変更属性が 1 つでもあると、提案は送れません。
5. 「変更を送る」を選び、必要ならメモや URL を添えて、送信前チェック（対象建物が 1 棟・
   XML が正しい・建物データ以外を変えていない・出典が記録済み）を通します。
6. 提案がこのリポジトリに作成されます。タイトルと説明はリポジトリの作業言語で自動生成されます。
   エディタに「GitHub で提出内容を見る」リンクが表示され、hub の投稿一覧にも並びます。

数分以内に自動検査が提案にコメントします。変更の要約、レビューしやすさの確認、14 項目の
検査表です。「要確認」の項目には対処方法が書かれています。エディタで直して同じ建物から
もう一度送ると、検査が再実行されます。すべて合格すると自治体の最終承認者が承認して、マージされます。
履歴に残る名前はあなたの GitHub アカウントで、通常の Pull Request と同じです。

## 7. 2 回目以降

デスクトップ・アイコンをダブルクリックします（または、同じワンコマンドをもう一度実行します —
安全に繰り返せます）。設定は省略され、hub が直接開きます。hub は
バックグラウンドで作業コピーを最新の状態に更新し、画面にその状態を表示します。提案が
「元の都市より古い」（base stale）と言われた場合は、同じ建物から再度送ってください。これは
同期が完了した後で行ってください。

ツールの新しいバージョンが公開されると、hub はバナーを表示します。「今すぐ取得」を
クリックするとダウンロードして検証し、次の起動から新しいバージョンが使われます。クリック
なしでダウンロードや再起動は行われません。

## 8. 練習リポジトリについて

サンプル都市は練習環境です。提案・コメント・レビューは本物の GitHub 履歴として残りますが、
データは定期的に基準状態へ戻されます。マージされた練習の変更が「正しい」必要はなく、
規則に沿っていることが大事です。実際の都市で作業する前に、自由に使ってください。

## 9. 困ったとき

- *ブラウザが今回と違うポートを開いた*: 別の hub が（別の都市で）いつもと同じポートで動いています。
  両方は動き続けます。各都市は独自のウィンドウを持ちます。
- *SHA-256 が一致しない*: ダウンロードが壊れたか改変されています。コマンドをもう一度
  実行してください。繰り返す場合は組織の
  [SUPPORT.md](https://github.com/4dcitygml/.github/blob/main/SUPPORT.md) の窓口へ。
- *`python3` や `git` が見つからない（macOS）*: `xcode-select --install` で
  Apple のコマンドラインツールをインストールして、もう一度実行してください。
- *設定は済んだのに設定画面が出る*: 作業コピーが移動または削除されています。もう一度
  取り込むか、`~/.citygml_attr_editor.json` （`cities`）で、この都市のエントリを
  新しい場所に指してください。
- *ツールが更新できない（オフライン）*: hub はインストール済みバージョンで動き続けます。
  バナーはオンライン時に戻ります。

## 10. ファイルの場所と削除のしかた

| 何 | どこ |
|---|---|
| ツール（バージョンごとに 1 フォルダ）とランチャースクリプト | `~/Documents/citygml-tools/` |
| デスクトップ・アイコン | ドラッグした場所（ランチャースクリプトを指すだけ） |
| 都市の作業コピー | `~/Documents/CityGML Data/` |
| アカウントと設定 | `~/.citygml/auth/`（接続した GitHub アカウントごとに 1 ファイル）、`~/.citygml_attr_editor.json` |

すべて消すには、上記を削除し、GitHub の *Settings → Applications → Authorized OAuth Apps*
で *4dcitygml hub* を取り消します。fork と送った提案は GitHub に残ります。不要なら
fork の設定ページから削除してください。

## 発展: Git・GitHub・自作ツール

hub がしていることはすべて通常の Git と GitHub の操作です。hub を使わなくても構いません。

- **手で clone・branch する**: このリポジトリ（または自分の fork）を `git clone` し、好きな
  エディタで CityGML を編集し、commit して Pull Request を開きます。GitHub のすべての機能が
  使えます: fork、branch、Web エディタ、Codespaces、API、CLI、自分の fork 上の Actions など。
- **規則はツールではなく Pull Request にあります**: 自動検査は、どう作られた提案にも同じ 14 の
  ゲートを適用します。最初の手動提案の前に、[PR 運用手順](pr-operations.md)（1 修正 = 1 建物、
  commit トレーラ、理由の節、バイト保存編集）、[出典記録の規則](provenance-rules.md)、そして
  機械可読な [PR Exchange Contract](https://github.com/4dcitygml/tools/blob/main/docs/exchange-contract.md)
  を読んでください。契約には CI が強制する内容がそのまま書かれ、CI と同じコードで動く
  ローカル検証器も案内されています。
- **自分のツールを作る**: 契約を満たす提案を作れるプログラムなら、スクリプトからフル機能の
  エディタ、QGIS プラグインまで歓迎です。管理者がクライアントを見分けられるよう
  `Created-By:` トレーラを付け、練習リポジトリをサンドボックスとして使い、
  `4dcitygml/tools` の issue で知らせてください。
- **hub のコピーの場所**: hub も併用する場合、その作業コピーは `~/Documents/CityGML Data/`
  配下の clone です。hub は接続先の都市を clone の `origin` から読むので、その clone を別の
  fork や branch に向け直しても期待どおりに動きます。
