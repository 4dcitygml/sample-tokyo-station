# はじめかた: クローンから最初の変更提案まで

<!-- 翻訳版です。内容に差がある場合は英語版（../getting-started.md）が正です。 -->

この案内は、練習の流れを最初から最後まで通して説明します。リポジトリを自分の PC に
取得し、共有編集ツールを起動し、GitHub アカウントとつなぎ、最初の変更提案
（Pull Request）を送るところまでです。初回は 15 分ほどかかります。都市データを直接
書き換える操作はありません。すべての編集は提案になり、管理者がレビューします。

提案が守るべき規則は [PR 運用手順](pr-operations.md) と [出典記録の規則](provenance-rules.md)、
投稿できる内容は [データ投稿ポリシー](data-contribution-policy.md) を参照してください。

## 1. 用意するもの

- GitHub アカウント（無料）。サインインは一度だけで、ツールが記憶します。
- macOS 12 以降、または Windows 10 以降。
- macOS のみ: Apple のコマンドラインツール（`git` と `python3`）。初回起動時に
  インストールを勧めるダイアログが出たら受け入れてください。他のインストールは不要です。
  Windows は何も要りません（Git と Python はダウンロード物に同梱）。
- ディスク空き容量 約 400 MB（ツールと都市データの自分用コピー）。

## 2. このリポジトリを取得する

どちらでも構いません。

- **クローン**（Git がある場合はこちらを推奨）:

  ```bash
  git clone <このリポジトリの URL>
  ```

- **ダウンロード**: リポジトリページの *Code → Download ZIP* を選び、展開する。

`install/`、`4dcitygml.json`、都市データが入ったフォルダができます。

## 3. ツールを起動する

- macOS: `install/start-mac.command` をダブルクリック。「開発元が未確認」と出たら
  右クリック → *開く*。ターミナルが書類フォルダへアクセスしてよいか聞かれたら許可します。
- Windows: `install/start-windows.bat` をダブルクリック。SmartScreen が出たら
  *詳細情報* → *実行*。

起きることの順番:

1. スターターが `install/tools-release.json` を読みます。ここにツールの正確な
   リリース（タグ・ファイル名・SHA-256）が固定されています。
2. そのリリースを `4dcitygml/tools` の Releases から取得し、チェックサムを検証します。
   一致しなければ何も展開せず停止します。
3. ツールを `~/Documents/citygml-tools/citygml-hub/` に展開します。
4. ブラウザで hub（`http://localhost:8760/`）が開き、この都市に接続済みの状態になります。
   作業中はターミナルの窓を閉じないでください。閉じるとツールが止まります。

ダウンロードは初回だけです。2 回目以降は手順 4 から始まります。

## 4. hub の初期設定（3 ステップ）

自分用の作業コピーができるまで、hub は 3 ステップの設定画面を表示します。

1. **つなぐ**: 画面に、許可する内容がそのまま書かれています。`public_repo` 権限で、
   公開リポジトリのコピー作成と Pull Request 作成をあなたの代わりに行えるようになります。
   *番号をコピーして GitHub を開く* を押し、開いた GitHub の画面に番号を貼り付けて承認します。
   サインインだけでは公開の痕跡は残りません。許可はあなた自身の GitHub 設定にだけ記録され、
   いつでも取り消せます。
2. **コピーを作る**: hub がこのリポジトリをあなたのアカウントに fork します。この時点から、
   コピーは GitHub の fork と同じく、あなたの名前で公開されます。
3. **取り込む**: hub がコピーを `~/Documents/CityGML Data/` に clone します（同名フォルダが
   あれば番号付きのフォルダになります）。大きな都市では数分かかります。

3 つ目が終わったら *はじめる* を押します。失敗した場合はボタンが再試行に変わります。
多くはネットワークの一時的な切断が原因です。

## 5. hub の画面

設定後、hub にはツールと自分の提案が並びます。

- **属性エディタ**: 地図から建物の属性を見て編集し、提案を送る。
- **テクスチャエディタ**: 外壁テクスチャの差し替え・追加（都市がテクスチャを持つ場合のみ）。
- **自分の提案**: 送った Pull Request と、自動検査の結果・レビュー状況。

各ツールは新しいタブで、それぞれのローカルポートで開きます。作業コピーの場所も hub に表示されます。

## 6. 最初の変更提案

属性エディタで:

1. 地図のメッシュ枠をクリックすると、そのメッシュの建物の足元が表示されます。
2. 建物をクリックすると、3D プレビューと属性カードが開きます。
3. 値をクリックして編集します。変更した値は黄色で示されます。
4. 値を確定すると同じ行に出典欄が開きます。確認した資料を選んでください。出典のない
   変更属性が 1 つでもあると、提案は送れません。
5. *変更を送る* を選び、必要ならメモや URL を添えて、送信前チェック（対象建物が 1 棟・
   XML が正しい・建物データ以外を変えていない・出典が記録済み）を通します。
6. 提案がこのリポジトリに作成されます。タイトルと説明はリポジトリの作業言語で自動生成され、
   hub がその提案を開きます。

数分以内に自動検査が提案にコメントします。変更の要約、レビューしやすさの確認、13 項目の
検査表です。「要確認」の項目には対処方法が書かれています。エディタで直して同じ建物から
もう一度送ると、検査が再実行されます。すべて合格すると管理者がレビューしてマージします。
履歴に残る名前はあなたの GitHub アカウントで、通常の Pull Request と同じです。

## 7. 2 回目以降

同じスターターをもう一度実行するだけです。設定は省略され、hub が直接開きます。検査で
「元の都市より古い（base stale）」と言われたら、GitHub で自分の fork を開いて
*Sync fork → Update branch* を押し、もう一度起動してください。

## 8. 練習リポジトリについて

サンプル都市は練習環境です。提案・コメント・レビューは本物の GitHub 履歴として残りますが、
データは定期的に基準状態へ戻されます。マージされた練習の変更が「正しい」必要はなく、
規則に沿っていることが大事です。実際の都市で作業する前に、自由に使ってください。

## 9. 困ったとき

- *ポート 8760 が使用中*: 別の hub が動いています。閉じるか、別のポートを指定します:
  `python3 ~/Documents/citygml-tools/citygml-hub/program/hub.py --port 8761`
- *SHA-256 が一致しない*: ダウンロードが壊れたか改変されています。スターターをもう一度
  実行してください。繰り返す場合は組織の
  [SUPPORT.md](https://github.com/4dcitygml/.github/blob/main/SUPPORT.md) の窓口へ。
- *`python3` や `git` が見つからない（macOS）*: `xcode-select --install` で Apple の
  コマンドラインツールを入れて、再起動してください。
- *設定は済んだのに設定画面が出る*: 作業コピーが移動または削除されています。もう一度
  取り込むか、`~/.citygml_attr_editor.json` の場所を新しい位置に書き換えてください。

## 10. ファイルの場所と削除のしかた

| 何 | どこ |
|---|---|
| ツール本体 | `~/Documents/citygml-tools/` |
| 都市の作業コピー | `~/Documents/CityGML Data/` |
| サインイン情報と設定 | `~/.citygml_auth.json`、`~/.citygml_attr_editor.json`、`~/.citygml_git_credentials` |

すべて消すには、上記を削除し、GitHub の *Settings → Applications → Authorized OAuth Apps*
で *4dcitygml hub* を Revoke します。fork と送った提案は GitHub に残ります。不要なら
fork の設定ページから削除してください。
